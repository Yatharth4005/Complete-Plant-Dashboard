# JSPL Unified Departments & Modules Hub (RGH Plant)

This repository contains the **JSPL Unified Operations Portal** for the RGH Plant. It acts as a Single Sign-On (SSO) central gateway, linking **28 departments** and **5 operational sub-departments/modules** (TPM, CMC, Production, Safety, HR) through a secure, permission-controlled landing hub.

---

## 1. System Architecture & Single Sign-On (SSO)

The project consists of two separate Django web services that integrate seamlessly through shared state:

1. **Main Portal Gateway (Runs on Port 8000)**:
   - Built using Django, CSS design systems, and Alpine.js.
   - Houses the central database models (`User`, `Department`, `Module`, `UserModuleAccess`, `AuditLog`).
   - Serves the Single Sign-In page and the master **Plant Dashboard** displaying all 28 department accordions.
   - Features the real-time **Access Control Matrix** admin panel, driven by **HTMX** for instantaneous permission updates.

2. **TPM Portal (Runs on Port 8001)**:
   - Houses the specific operational sub-system for **Total Productive Maintenance (TPM)**, containing 8-pillar KPI checklists and workstation sheets.
   - Resides in the `TPM Portal/` subfolder.

### How the SSO Works:
- **Shared SQLite Database**: Both Django servers point to the same shared database file (`db.sqlite3` located at the root of this workspace).
- **Session Sharing**: Both projects share matching cryptographic secret keys and session cookie configurations. Because web browsers isolate cookies by domain name (e.g. `localhost` or `127.0.0.1`) but **ignore ports**, the session cookie (`sessionid`) generated by logging into Port 8000 is automatically sent to Port 8001.
- **Seamless Transition**: When a user selects the unlocked **TPM** card on the main dashboard, they are redirected to port 8001. The TPM server reads the session cookie, queries the shared database sessions, and authenticates the user instantly with zero re-login.

## 2. Main Dashboard & Sidenav Features

- **Department Accordions**: All 28 plant departments are displayed as clean, compact cards. Clicking a card expands it downward to reveal its modules list. Clicking again collapses it.
- **Smart Auto-Expansion**: The landing dashboard checks the logged-in user's profile and automatically expands their assigned primary department (e.g. `SMS2` expands automatically for SMS-2 users).
- **Responsive Sidenav Toggling**: A collapse menu toggle (`☰`) is present in the topbar on both desktop and mobile views. The sidebar retracts smoothly with CSS width slide transitions.
- **Access Control Matrix**: Admins can visit `/admin/access/` to view and update access levels (EDIT, VIEW, NONE) for all users across all departments in real-time.

## 3. Installation & Setup Instructions

Follow these step-by-step instructions to get both portals running locally:

### Step 1: Set Up the Virtual Environment
Create and activate a Python virtual environment.
```bash
# Navigate to the TPM Portal subfolder and create/activate the virtual environment
cd "TPM Portal"
python -m venv venv

# On Windows (CMD):
venv\Scripts\activate
# On Windows (PowerShell):
.\venv\Scripts\activate
# On Linux/macOS:
source venv/bin/activate

# Return to root workspace
cd ..
```

### Step 2: Install Dependencies
Install Django and database adapters.
```bash
pip install django
```

### Step 3: Initialize the Shared Database
Move the existing database file from the `TPM Portal` subfolder to the root workspace folder:
```bash
# Windows (PowerShell)
Move-Item -Path "TPM Portal\db.sqlite3" -Destination "."
```

### Step 4: Apply Database Migrations
Apply the unified custom database tables and fields across both projects:
```bash
# 4a. Apply migrations on the custom User model inside the TPM Portal directory
cd "TPM Portal"
python manage.py makemigrations tpm
python manage.py migrate
cd ..

# 4b. Apply migrations on the main portal registry models
python manage.py makemigrations portal
python manage.py migrate
```

### Step 5: Seed the Portal Data
Populate the registry with the 28 plant departments, 5 core modules, and test users:
```bash
python manage.py seed_portal
```

---

## 4. Running the Development Servers

Open two terminals with the virtual environment activated, and run:

* **Terminal 1: Main Portal (Port 8000)**
  ```bash
  python manage.py runserver 8000
  ```

* **Terminal 2: TPM Portal (Port 8001)**
  ```bash
  cd "TPM Portal"
  python manage.py runserver 8001
  ```

Once both servers are running, access the portal via:
`http://localhost:8000/`

---

## 5. User Credentials & Roles

Once you run the `seed_portal` command, standard test users and role-based access assignments are populated. You can review the profiles and modify them within the seed script at `portal/management/commands/seed_portal.py`.

To create a new custom administrator account with full privileges on your local system, run:
```bash
python manage.py createsuperuser
```
